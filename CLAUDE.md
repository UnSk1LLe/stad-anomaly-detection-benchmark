# Контекст проекта для Claude Code

Прочитать целиком перед первым изменением в этом репозитории.

## Что это

Эксперимент для PhD по обнаружению аномалий в дорожном трафике. Цель —
обоснованно выбрать архитектуру для диссертации, а не получить
максимальное число в таблице. Полное описание — `README.md`,
протокол — `docs/PROTOCOL.md`, правила вывода — `docs/DECISION_RULES.md`.

Связанный контекст диссертации лежит в Obsidian-хранилище пользователя:
`PhD FRL/claude.md` (зона ответственности, план глав, открытые пробелы),
`PhD FRL/Literature 25-26/00 Индекс.md` (126 статей),
`PhD FRL/Datasets/00 Индекс датасетов.md` (34 датасета).

## Главные правила, которые нельзя нарушать

Это не стилистические предпочтения. Нарушение любого из них делает
результаты эксперимента недействительными.

1. **Не ранжировать модели по point-adjustment F1.** Ключ называется
   `pa_f1_INVALID_for_ranking` намеренно. Он существует только для
   фигуры 05, демонстрирующей инфляцию.

2. **Не выбирать лучший сид.** Агрегация по сидам — среднее. При
   «best-of-N» отчётности часть метрик становится обманываемой
   (Lyu, 2026). Число сидов раскрывается в `manifest.json`.

3. **Не подбирать порог по тестовым меткам.** Порог задаётся бюджетом
   ложных тревог на нормальных точках. Oracle-F1 репортится только как
   верхняя граница.

4. **Не ломать протокольные контроли.** `ctrl_random`, `ctrl_untrained`
   и `base_pca` входят в каждую сетку. Если случайный контроль поднялся
   в верхнюю половину таблицы — это дефект метрики, а не удача модели.
   Чинить метрику, а не убирать контроль.

5. **Не выравнивать результаты удалением бейзлайнов.** Если классический
   California-алгоритм обходит ST-GNN — это результат для обсуждения,
   а не повод его убрать.

6. **Не менять бюджет параметров ради одной архитектуры.** Он общий и
   фиксируется до прогона.

7. **Не переносить выводы с синтетики в диссертацию.** Синтетика
   объясняет механизм; итог делается на FT-AED с реальными метками.

8. **Не подмешивать синтетику в обучение основной сетки.** Её
   конфигурации unsupervised и учат норму; синтетические аномалии в
   `X_train` загрязнят модель нормы. Аугментация редкого класса живёт
   в отдельном supervised-арме (`src/stad/augment`), и синтетика
   никогда не попадает в тестовую выборку.

9. **Не оценивать FT-AED поузловыми метриками.** Метки там
   корридор-уровневые; `evaluation_view` сводит score к их
   гранулярности. Обход этой функции завышает event-recall любого
   детектора, включая случайный.

10. **Якорить шаблоны в .gitignore.** `data/` без ведущего слэша
    матчит любой каталог с таким именем — из-за этого из репозитория
    молча выпал весь `src/stad/data/`. Проверять состав коммита
    через `git ls-files`, а не доверять `git status`.

11. **Решающие правила фиксированы до прогона.** Менять
   `docs/DECISION_RULES.md` после того, как увидел числа, — подгонка.
   Если правило действительно требует изменения, зафиксировать причину
   в сообщении коммита.

## Рабочий цикл

```bash
make test      # всегда перед коммитом
make smoke     # пайплайн целиком на синтетике, минуты
make figures   # пересборка фигур без обучения
```

Любое изменение в `src/stad/metrics/` обязано сопровождаться тестом.
Это самая опасная часть репозитория: сломанная метрика даёт
правдоподобные, но бессмысленные результаты.

## Архитектура кода

Контракт один и соблюдается везде:

```
данные    [n_windows, N_nodes, T_steps, F_features]
энкодер   [B, N, T, F] -> [B, N, H]
голова    [B, N, H] (+ x) -> score [B, N],  больше = аномальнее
```

Добавление новой архитектуры:

1. Энкодер — в `src/stad/encoders/`, наследник `Encoder`, зарегистрировать
   в `ENCODERS` и `ENCODER_LABELS`.
2. Голова — в `src/stad/heads/`, наследник `Head`, зарегистрировать
   в `HEADS`, `HEAD_LABELS`, `HEAD_MECHANISM`.
3. Конфигурация — в `src/stad/registry.py`, **обязательно с полем
   `rationale`**: зачем она в сетке. Это поле попадает в отчёт; без
   него при 12–27 конфигурациях теряется смысл эксперимента.
4. Тест на форму выхода и отсутствие утечки добавляется автоматически
   через параметризацию в `tests/test_models.py`.

Если голова работает на остатке прогноза, выставить `splits_window` и
`forecast_horizon`: деление окна выполняется в `Detector._split`, в
одном месте, чтобы утечка цели не просачивалась незаметно.

## Известные тонкости

- **Время события** (`events.t_report`) и **время окна** (`t_test`)
  измеряются в минутах от первого отсчёта, в одной шкале. Смещение
  между ними — источник ошибки, которая уже случалась: задержки
  завышались ровно на длину окна.
- **Подтверждение тревоги** (`persistence = 3`) влияет на все
  event-level метрики. Порог при этом подбирается бинарным поиском,
  потому что подтверждение — нелинейная операция.
- **Чекпойнты** пишутся в `reports/<прогон>/checkpoints/` вместе с
  рецептом сборки: `hidden` подбирается под бюджет параметров, и без
  него модель не восстановить. Матрица смежности и статистики
  нормализации тоже в чекпойнте — подстановка других тихо изменила бы
  поведение. Отключается `save_checkpoints: false` в конфиге.
- **Критик BiGAN** обучается отдельным оптимизатором; его параметры
  исключены из `main_parameters()`.
- **Physics-голова** требует порядка узлов вдоль коридора и признаков
  занятости и объёма; число полос передаётся из метаданных датасета.
- **Фигуры**: палитра валидирована программно; для диаграмм рассеяния
  допустимы только первые три категориальных слота; двух осей Y не
  бывает; у каждой фигуры есть CSV-двойник.

## Запуск тяжёлых прогонов

`make ft-aed` — 12 конфигураций × 5 сидов на 196 узлах. На CPU это
долго; при наличии GPU передать `--device cuda`. Прогон одной клетки не
роняет сетку: ошибки собираются в `failures.csv`.
